# Repo CI (phase 5a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GitHub Actions runs `tests/render-all.sh` for all five stacks in parallel on every PR into `main` and every push to `main`.

**Architecture:** One workflow file at the repo root with a 5-way stack matrix. Each job installs only its stack's toolchain and calls the existing script unchanged. A separate small job runs `git diff --check` on PRs.

**Tech Stack:** GitHub Actions (ubuntu-latest), bash, uv, Node 24, .NET 10, Go 1.26, rustup + cargo-deny, Docker (preinstalled on the runner).

**Spec:** `docs/superpowers/specs/2026-11-18-repo-ci-design.md`

## Global Constraints

- Workflow path: `.github/workflows/render-all.yml` at the repo root — never under `template/`.
- Triggers: `pull_request` (branches: `main`), `push` (branches: `main`), `workflow_dispatch`; `paths-ignore: ["README.md", "docs/**"]` on `pull_request` and `push`.
- `concurrency: { group: render-all-${{ github.ref }}, cancel-in-progress: true }`.
- Matrix `stack: [typescript, python, dotnet, go, rust]`, `fail-fast: false`, `runs-on: ubuntu-latest`, `timeout-minutes: 120`.
- Action versions: `actions/checkout@v4`, `actions/setup-node@v4` (node-version `24`), `astral-sh/setup-uv@v6`, `actions/setup-dotnet@v4` (`10.0.x`), `actions/setup-go@v5` (`1.26.x`), `taiki-e/install-action@v2` (tool `cargo-deny`).
- `tests/render-all.sh` is not modified.
- Branch: `feat/phase5a-repo-ci`; commit messages end with the `Co-Authored-By` line from the session.

## Review Focus

1. A PR that only touches `template/docs/**` must still trigger the run (paths-ignore is `docs/**` anchored at root, which does not match `template/docs/...`) — check in Task 1 with the pattern reasoning and in Task 3 by the PR's own run.
2. Browser tests on a bare runner: Playwright needs system libraries; without `install-deps` the TypeScript frontend checks fail for reasons unrelated to the template — Task 1 adds it, Task 3 confirms.
3. A failing stack must not cancel the others (`fail-fast: false`) — Task 3 confirms all five report independently.
4. The script must fail the job: it exits 1 on any FAIL — Task 3 confirms a red job shows the FAIL lines in the log.
5. Disk space: five-plus datastore images (Oracle, SQL Server) in one TypeScript job may fill the runner disk — Task 3 watches for `no space left on device`; fix by adding a cleanup step before the script.
